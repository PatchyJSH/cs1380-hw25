1. What are the base case and recursive case for your factorial?
    The base case is when n <= 1, which returns 1 because 0! and 1! are both defined as 1. The recursive case is n * factorial(n - 1), which reduces the problem to a smaller factorial until the base case is reached.

2. What goes wrong if you omit the base case?
    Without a base case, the function would continue calling itself forever because there is no condition that stops the recursion. This eventually causes a stack overflow and the program crashes.

3. Why does naive fib(n) repeat work? (One or two sentences is enough.)
    The naive recursive Fibonacci function recalculates the same values many times while solving larger problems. For example, fib(3) is computed multiple times when evaluating fib(5).

4. For max_in_array, what shrinks on each recursive call?
    The portion of the array being considered becomes smaller on each call. This happens because the function advances the pointer with a + 1 and reduces the size parameter from n to n - 1.

5. When might a loop be a better fit than recursion for scanning an array?
    A loop is often better when performance and memory efficiency are important because it avoids the overhead of multiple function calls. For a simple array scan, an iterative solution is usually easier to read and more efficient.
